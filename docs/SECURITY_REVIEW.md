# Security review (version 0.1.0)

Scope: the extension's permissions, content script, background worker, extension pages and DOM handling, and the
build. Reviewed by the maintainers on 2026-10-19 before the first release; findings that needed a change were fixed
and are covered by tests.

## Threat model

Assets: the text a user pastes or tries to send (it may contain personal data or credentials), and the user's
settings (custom words may themselves be sensitive).

Adversaries considered:

1. **The chat site's own scripts**, including third-party analytics or session recorders loaded by the site. They can
   read and change the page DOM and dispatch events.
2. **Other websites** the user visits.
3. **A compromised dependency** in the build.

Out of scope: malware on the device, other extensions with broad permissions, a malicious browser.

## Findings and measures

| #   | area                  | finding / risk                                                                                                                                                            | measure                                                                                                                                                                                                                                                                                                                                   | test                                                          |
| --- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 1   | content script        | Content scripts at `document_idle` run after the page's scripts; a page listener registered earlier would receive a paste (and its text) before SafePrompt could stop it. | Run at `document_start`; listeners on `window` in the capture phase call `stopImmediatePropagation()`.                                                                                                                                                                                                                                    | `the page's own paste listener never sees a blocked paste`    |
| 2   | dialog                | Rendering findings in the page DOM would expose the values to the page and to session recorders.                                                                          | The dialog is `review.html` (extension origin) in an iframe inside a closed shadow root. Values are never written to the page DOM.                                                                                                                                                                                                        | `the site's scripts cannot read the review dialog`            |
| 3   | messaging             | A page could try to read sessions or impersonate extension pages.                                                                                                         | No `externally_connectable`; the background accepts `review:open` only from content scripts (`sender.tab`) and `review:get` / `review:done` only from the extension's `review.html` (checked by protocol and path; `sender.id`). Session ids are 128-bit random. `chrome.storage.session` keeps its default trusted-contexts-only access. | unit-reviewed                                                 |
| 4   | events                | A page could dispatch synthetic paste events to open SafePrompt's dialog repeatedly.                                                                                      | Paste checks require `event.isTrusted`. SafePrompt's own synthetic paste (used to insert text into rich editors) is marked with an internal flag.                                                                                                                                                                                         | `synthetic paste events from the page do not open the dialog` |
| 5   | availability          | A page removing the dialog would leave the review pending and block later checks.                                                                                         | The content script treats a removed dialog as _Cancel_.                                                                                                                                                                                                                                                                                   | `if the page removes the dialog, checks keep working`         |
| 6   | dialog                | The page can navigate the dialog frame (parents may navigate child frames) and show its own content there.                                                                | Such content cannot obtain session data or produce a result: results come only from the background for a valid session id. Residual risk: UI spoofing inside the frame; accepted (the page can already show anything).                                                                                                                    | —                                                             |
| 7   | storage               | Pending reviews could linger after a tab closes.                                                                                                                          | Stored only in `chrome.storage.session` (memory); deleted on decision, on tab close and after 10 minutes.                                                                                                                                                                                                                                 | `nothing is stored except settings`                           |
| 8   | DOM                   | User text rendered as HTML would allow script injection into extension pages.                                                                                             | All text is inserted with `textContent`; ESLint forbids `innerHTML`, `outerHTML` and `insertAdjacentHTML` in source. CSP for extension pages: `script-src 'self'; object-src 'none'; base-uri 'none'`.                                                                                                                                    | lint                                                          |
| 9   | network               | Any network access would contradict the privacy promise.                                                                                                                  | No network code; ESLint forbids `fetch`. The extension declares no host permissions beyond the chat sites. Playwright tests abort all requests to the internet.                                                                                                                                                                           | lint, e2e                                                     |
| 10  | permissions           | Broad host access (`<all_urls>`) is a common risk in privacy extensions.                                                                                                  | Fixed list of chat sites; other sites only through `optional_host_permissions`, one origin at a time, and registered with `chrome.scripting.registerContentScripts`.                                                                                                                                                                      | manual                                                        |
| 11  | fingerprinting        | Web-accessible resources reveal the extension id.                                                                                                                         | `use_dynamic_url: true` for `review.html`.                                                                                                                                                                                                                                                                                                | manual                                                        |
| 12  | supply chain          | Runtime dependencies are bundled into the extension.                                                                                                                      | One runtime dependency (`libphonenumber-js`, MIT). Exact versions in `package-lock.json`; `npm audit --omit=dev` in CI; reproducible zip with published SHA-256. Development-only dependencies (test editors) are not shipped.                                                                                                            | CI                                                            |
| 13  | false sense of safety | Claiming protection where the integration does not work.                                                                                                                  | The badge and side panel claim protection only when the message box is found on the page; untested integrations are labelled; Claude is off by default.                                                                                                                                                                                   | e2e, manual                                                   |

## Residual risks

- Detection can miss data (names, addresses, unlabelled numbers). The interface says so.
- _Send unchanged_ and _Paste original_ deliberately let the original text through.
- Sites can change their pages so that the send check no longer finds the message box. The status indicator shows
  this, but a user who does not look may assume protection.
- The page can see that SafePrompt is installed (a dialog appears; events are stopped).
- `npm audit` reports a low-severity advisory in `quill`, used only to build test pages; it is not shipped.
