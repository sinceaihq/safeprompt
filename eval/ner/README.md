# SafePrompt NER study: can a small in-browser model find names and places?

> **Decision for SafePrompt v0.1.0 (2026-10-19): no NER layer ships.** The study below recommends an opt-in
> names-and-places hint, but three things must be settled first: (1) the recommended weights were trained on
> corpora with research-only terms (CoNLL-2003), which needs a legal view before redistribution or a download
> prompt inside the extension; (2) recall on lower-case names — common in chat — is 13–33 % for the licensable
> candidates (distilmBERT-HRL 12.6, nym-small 33.4); (3) in-browser (WASM) latency is unmeasured. SafePrompt v0.1 therefore detects structured identifiers
> and secrets only, and says so. The fine-tune proposal in §8 is the v0.2 track.

**Question.** Can a compact multilingual NER model, run in the browser (onnxruntime-web /
transformers.js, int8 ONNX), meaningfully improve SafePrompt's detection of **person names**
and **locations** (maybe organisations) in European-language chat prompts, with acceptable
false positives, size and latency? The deterministic engine (checksummed IDs, IBAN, VAT, phone,
e-mail, secrets) finds none of these.

**Short answer.** It helps, but only for **properly capitalised text**. On gold real-text
corpora in 11 EU languages the best model that fits the ~150 MB budget
(distilmBERT-HRL, int8, 135 MB) finds **88 % of person mentions at 93 % precision**
(overlap F1 90.6) and 88 % F1 on locations, with about **1 false person/place per 1,000
tokens** of ordinary text and none in 6.7k tokens of code. But on **lower-cased** text,
which is common in chat, its person recall drops to **13 %** (5 % on lower-cased chat prompts),
and no small model tested is robust to that. The recommendation is **(a), with limits**:
ship it as an **optional, opt-in "names & places hint" layer** (PER + LOC, threshold 0.5,
ORG off). Describe it as best-effort, never as a guarantee, and do not use it to show a
prompt is "clean". A lower-casing-robust fine-tune is the clear next step (proposal in §8).

All numbers below are from `results/` (JSON) and were generated by the scripts in `scripts/`.
`results/tables.md` holds every table, including the sections left out here.

## 1. Method

### Pipeline

1. `scripts/download_data.py` downloads raw corpora into `eval/cache/raw/` (gitignored).
2. `scripts/prepare_data.py` normalises them to `{text, spans[PER|LOC|ORG], ignore[...]}` and
   takes **seeded samples** (seed `20261019`, per-set RNG `Random("20261019:<split>:<set>")`):
   **500 sentences per test set** and 300 per dev set. Tokens are joined with light
   detokenisation (no space before `, . ; : ! ?` etc.). The output stays in `eval/cache/prepared/`
   because several licences do not allow redistribution. `results/data_manifest.json` records
   the pool size, sample size, entity counts and a hash of the selected ids for every set.
3. `scripts/run_eval.py MODEL` runs one model over every prepared set (onnxruntime 1.31 CPU,
   `intra_op=6`, `nice 15`) and stores raw predictions **without a threshold**.
   `scripts/run_all.sh` runs the models one after another.
4. `scripts/score.py` scores the predictions, sweeps thresholds 0.30–0.95 and **selects the
   operating point on dev only**: per type, it maximises the macro overlap-F1 over 10 real-text
   dev sets, plus EuroPII _dev_ for PER. The test sets are never used for tuning.
5. `scripts/bench.py MODEL --threads {1,4}` measures latency, RSS and size in a fresh process.
6. `scripts/make_report.py` writes `results/tables.md` + `results/summary.json`, and
   `scripts/examples.py` writes the qualitative errors to `results/examples/`.
   Helpers: `scripts/export_gliner.py` and `scripts/quantize.py` (GLiNER export/quantisation),
   `scripts/handwritten.py` (the two sets written for this study).

Environment: `python3 -m venv .venv-ner`,
`pip install -r requirements.txt` (pinned), `HF_HOME=eval/cache/hf`. Everything ran on CPU.

### Decoding (token-classification models)

This is the same word-level scheme that bardsai ships in its reference `pii_detector.py`, but
with labels pooled into coarse types. A browser implementation would do the same on the raw
logits:

- per-token softmax. The probabilities of all raw labels that map to the same coarse type are
  summed (e.g. `B-/I-GIVEN_NAME` + `B-/I-SURNAME` → PER).
- words = regex split on whitespace and `, ; | " < > ( ) [ ] { } * ^`, with edge punctuation
  trimmed. A word's distribution is the mean of its sub-tokens, and its label is the argmax over
  {O, PER, LOC, ORG, OTHER}.
- adjacent words of the same type are merged across whitespace/hyphen unless the next word
  starts a new entity (B-mass ≥ 0.5 with the same fine label).
- span score = the mean word probability. The threshold is applied to that score.

Label mapping: Davlan `PER/LOC/ORG`. bardsai `PERSON_NAME, PERSON_ALIAS → PER`;
`LOCATION, GEO_LOCATION, POSTAL_ADDRESS → LOC`; `ORGANIZATION_NAME → ORG`. nym
`GIVEN_NAME, SURNAME → PER`; `CITY, COUNTRY, STATE, STREET_ADDRESS, STREET_NAME → LOC`;
`COMPANY_NAME → ORG`. GLiNER prompts are `person`, `location` and `organization`, run with the
regex word splitter that gliner.js uses (gliner-x's config asks for Stanza, which does not exist
in a browser). All other labels become `OTHER`, which counts only towards type-agnostic coverage.

### Metrics

- **exact** P/R/F1 on (start, end, type).
- **overlap**: a gold span is _recalled_ if any of its characters is covered by a same-type
  prediction, and a prediction is _correct_ if it overlaps a same-type gold span. This is the
  metric that matters for a warning or redaction UI, and it is the headline metric.
- **any-type coverage**: a gold PER is covered by a prediction of _any_ type (e.g. a name tagged
  ORG still triggers a warning).
- **FP rates per 1,000 whitespace tokens**: on the author-written negatives, on stdlib code, on
  EuroPII, and "spurious" predictions on real text that overlap no gold entity at all (this
  includes annotation gaps, so it is an upper bound).
- Gold entities of classes outside PER/LOC/ORG (MISC, products, events, facilities, GermEval
  `*deriv/*part`) are _ignore regions_: a prediction that overlaps only such a region is neither
  rewarded nor penalised.
- Bootstrap 95 % CIs (500 resamples of sentences) for the PER/LOC results of the recommended
  model are in `results/tables.md`.

sending; it should run in an offscreen document or worker. RSS includes the Python
interpreter. The model's own working set in the browser should be roughly
ONNX size + 100–200 MB.

## 5. Candidates not fully evaluated / caveats per model

- **urchade/gliner_multi_pii-v1: not fully evaluated (time-boxed).** The `onnx-community` int8
  export returns only flat ~0.15–0.19 scores with the current gliner runtime, verified with the
  original tokenizer. A fresh export with `gliner.export_to_onnx` works in fp32. Dynamic int8
  quantisation (gliner default QUInt8, 349 MB) degrades it badly ("Aino Virtaselle" PER 1.00 →
  0.39, "Tampereella" LOC → ORG). Per-channel QInt8 MatMul-only gave no entities and 931 MB.
  The fp32 run was stopped after the dev split. On dev it reached PER macro F1 **79.3** and LOC
  **68.6** (best thresholds 0.95 / 0.55), against 90.6 / 87.7 for distilmBERT-HRL on the same
  dev sets. It is not competitive, and at 349 MB+ it is far over budget.
- **bardsai v2** (`onnx/model_quantized.onnx`): poor LOC/ORG typing (LOC F1 31) and low,
  diffuse confidences. It does _notice_ names (any-type coverage 97 %) but often under the wrong
  label. On two test sentences its fp32 ONNX logits differed from the PyTorch weights by up to
  2.2 (transformers 4.57, ModernBERT), and the PyTorch model was also low-confidence. The ONNX
  export or our runtime versions may be at fault, so this is not a verdict on the v2 weights.
  Its int8 artifact is 309 MB, over budget anyway. A PyTorch-weights run
  (`bardsai-v2-torch-fp32` in `scripts/models.py`) was prepared but not run (time-box).
- **bardsai-mini-preview**: the most case-robust small model (lower-case probe 44.7 % recall,
  lower-cased chat 75 %, 107 MB, fastest), but it declares **no licence** and calls itself a
  preview "under training", so it **must not be shipped**. It also has more false positives
  (3.2 LOC/1k on negatives, 1.8 PER/1k on code).
- **nym-small** int8 (embedding int8 + fp16 weights) and edge-int8 differ by ~2 F1. The
  model is MIT, but part of its training corpus is undisclosed real text.
- **Davlan HRL models**: CoNLL-2002 es/nl were in their training data (train split; we test on
  testb), which inflates es/nl. Their training data also includes CoNLL-2003 (Reuters RCV1,
  research-only licence terms) and I-CAB. The _weights_ are released under AFL-3.0, which is
  permissive and allows commercial use but requires keeping the licence notice. Whether
  weights trained on research-only corpora may be redistributed commercially is a **legal
  question to clear before shipping**.

## 6. Qualitative errors (distilmbert-hrl int8, `results/examples/`)

- **Lower-case names are invisible:** "can you write a polite reminder to ⟦sarah o'connell⟧ …
  she lives in ⟦cork⟧", "hi ⟦jake⟧ … regards, ⟦anna⟧", "kannst du die mail an ⟦jürgen schäfer⟧
  umformulieren? er sitzt in ⟦stuttgart⟧", "résume ce message : ⟦pierre⟧ ne viendra pas".
- **Names typed as ORG** (still caught by type-agnostic coverage): "Hi, this is ⟦Ciarán Ryan⟧."
  → ORG, and "Supplier ⟦Aoife O'Sullivan⟧ Ltd" → ORG for the whole company name. EuroPII
  labels the person inside it; arguably both are right.
- **Confident false positives on capitalised non-names:** "⟦Hallo⟧, met Joost Bakker" (Dutch
  greeting → PER, 0.98–1.0), "Correggi: ⟦Gentile⟧ dott.ssa Romano" (Italian salutation → PER),
  "⟦Rätta⟧:" (Swedish imperative → LOC), "TypeError: ⟦Cannot⟧ read properties" → PER,
  "Cara ⟦Dra⟧. Martins" → LOC.
- **Finnish inflection and informal names:** misses nicknames ("Teltsu", "Krobs") and some
  inflected forms. "Tyttö" ("girl") at the start of a sentence → PER.

**If 178 MB is acceptable:** `Xenova/bert-base-multilingual-cased-ner-hrl` `onnx/model_quantized.onnx`

~2× the compute. Its threshold is PER 0.55, LOC 0.3 (dev-selected). LOC 0.5 changes LOC F1 by

`int8/model_int8.onnx` (MIT, 139 MB, PER 0.5 / LOC 0.55). It has lower recall on cased real
text (80.8 % vs 88.4 %) but is better on lower-case (33 % vs 13 %) and had zero hits on the
negatives.

int8 breaks the mDeBERTa variant), and the NC/ND-licensed models.

## 8. Proposal: close the lower-case gap with a CPU fine-tune (not done)

The gap is clear and measurable: **87 % → 13 %** PER recall when the same sentences are
lower-cased. The literature (Mayhew et al., 2019, "NER and POS when nothing is capitalized")
shows that training on a **mix of cased and lower-cased copies** recovers most of it at little
cost on cased text.

- **Data (legitimately licensed, PER/LOC):** UNER v1 train splits (da, en, hr, pt, sk, sv,
  zh/sr not needed; CC BY-SA 4.0), Turku NER train (fi, CC BY-SA 4.0), GermEval 2014 train
  (de, CC BY 4.0), KPWr train (pl, CC BY 3.0) and MultiCoNER II train (7 langs, CC BY 4.0,
  already lower-cased). That is ~60–80k sentences, plus a lower-cased copy of each cased
  sentence, plus a few thousand synthetic chat-style templates in the style of EuroPII with
  lower-cased variants. Hold out the test sets above. Note: CC BY-SA training data may impose
  share-alike obligations on the weights. Get a legal view, or use only the CC BY sets
  (GermEval, KPWr, MultiCoNER, WNUT) plus the synthetic data.
- **Model:** continue from `distilbert-base-multilingual-cased` (Apache-2.0) or from the
  Davlan HRL checkpoint (inherits its provenance question). A cleaner option is
  `jhu-clsp/mmBERT-small` (MIT), which nym shows survives int8 at ~110–140 MB.
- **Cost:** distilmBERT (66M params, 6 layers), seq 128, batch 32, 2–3 epochs over ~150k
  sentences ≈ 10–15k steps. On 6 CPU threads this is ~0.3–0.5 s/step, so **~1.5–2 h per
  epoch, 3–6 h in total**. No GPU is needed. Evaluation is ~10 min with these scripts.
- **Success criterion:** lower-case probe PER recall ≥ 70 % and cased primary PER F1 within
  1 point of the current 90.6, at the same false-positive rates on the negatives and code.

## 9. Limitations

- 500-sentence samples per set give ±3–8 points per-language CIs (see the bootstrap table).
  The macro numbers are more stable.
- There is no real chat-log corpus with gold names. EuroPII is synthetic and templated, and
  the chat and negative sets are small and written by the author of this study. The case
  finding, however, is consistent across 3 independent sources (lower-case probe, MultiCoNER,
  chat prompts).
- Annotation conventions differ (titles, nested entities, facilities, KPWr fine-grained mapping
  in `prepare_data.py`), which is why overlap metrics are the headline. Exact F1 is reported too.
- French and Italian have no cased gold set here, only silver WikiANN (all models 85–90 F1).
- Latency was measured natively under heavy, uncontrolled server load. Browser WASM numbers
  must be measured in the extension.
- Only dynamic int8 (as shipped on the hub) was tested. fp16 and q4 variants were not.
- Decoding is our own (word-level, documented above). Models with their own recommended
  decoders (bardsai v2) might score differently with those.
